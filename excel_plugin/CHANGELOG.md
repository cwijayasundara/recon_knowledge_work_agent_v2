# Changelog

## Unreleased

- Copilot (stage 2, off unless the server sets `ONB_COPILOT_ENABLED=true`): a **Copilot** header button opens a panel where an analyst asks about the open workbook. A pane-driven step loop calls the server for one model step at a time and runs the requested tools in Excel: `list_sheets`, `describe_sheet`, `read_range`, `find`, `get_selection` (capped; the tools never read hidden and very-hidden sheets directly, though a visible formula referencing one shows its value; hidden rows are read). With a run open it can also read the run's state and findings and dry-run typed changes. It only proposes: write proposals (diff card; **Apply to Copilot Scratch**, or **Apply to range…** with a second confirmation and a live before-values read at click; formulas need confirmation even on scratch) and typed changes (the stage-1 proposal card, minus `acknowledge_finding`). It cannot approve, acknowledge or pass a gate and has no history, upload, network or shell tool. The answer lists what it read ("What the copilot read"), the privacy notice states that read cells go to the server's AI model, and Stop ends a turn.
- Copilot safety: caps enforced on the server (cells per call and per session, cell length, steps per turn, write cells), fixed result shapes, tool results wrapped as untrusted data, a formula denylist on both sides (external and side-effecting functions, `INDIRECT`/`CELL`/`INFO`, `IMPORTTEXT`/`IMPORTCSV`, bare function names (also behind stacked `_xlfn.`/`_xlws.` prefixes), `_xll.`/`_xludf.` add-in and UDF names, external workbook, DDE, UNC and URL references, and references to hidden sheets through names, tables and 3D references), a values policy (no leading `=+@-`, tab or CR unless numeric; written as text), ownership markers (`CopilotScratchOwner`) so only the add-in's own scratch sheet is cleared, merged/protected/hidden targets refused, a stale-preview refusal, per-actor session cap (5) and a per-API-process concurrent-step limit with 503 and `Retry-After`. A scratch write over earlier scratch content asks first. Audit logs carry addresses and counts only.
- Copilot client hardening: a 5-minute turn bound, 120 s per step, busy retries that honour `Retry-After` (clamped 1-60 s, twice), a background retry for closing a session whose step still runs, one session per run (after a run change, the old session is closed when the next message is sent, when the pane closes, or by its TTL), Apply of typed changes disabled once the run state has moved on, size-based batching of tool results (the server caps a request at 2 MiB).
- New API surface (server): `POST /copilot/sessions`, `POST /copilot/sessions/{id}/step`, `DELETE /copilot/sessions/{id}` (403 disabled, 404, 409, 413, 415, 422, 429, 503); settings `ONB_COPILOT_*` (see README); model role `copilot` (`gpt-5.6-terra` locally); CORS exposes `Retry-After`. `ONB_CORS_ORIGINS` must include the add-in origin.
- Dev server (`vite.config.ts`, dev only): uses `~/.office-addin-dev-certs/localhost.{key,crt}` when present (trusted by desktop Excel), else Vite's self-signed certificate; proxies `/api` to `DEV_API_TARGET` (default `http://localhost:8000`) so `VITE_API_BASE=https://localhost:3100/api` calls the API same-origin.
- Testing: the scripted server takes `--copilot` (keywords `overcap`, `propose formulas`, `propose changes`, `propose write`, `inject`, `slow`, `sheets`), and the contract test runs two servers (copilot on and off). Known limits and the real-Excel checklist are in the README.
- Chat (stage 1, "Ask the agent"): a **Chat** header button toggles a panel whose composer posts `instruct` only on Send (or Ctrl/Cmd+Enter) at the brief and findings gates, never while a gate action is held or a reply is pending; the reply is read from a snapshot after the instruction's own decision and idle (restatement, server message, or the re-scoped brief), and a findings-gate proposal shows as a card whose **Apply** posts exactly its changes, once, while the run still offers it. The chat cannot approve or acknowledge (proposals with an acknowledgement are not applyable from it); re-scoping proposals are labelled and report "Sent. The run is re-scoping — check the brief." No new endpoints; conversation kept in memory per run.
- Sign-in gets its own 180 s bound before the 30 s request bound; concurrent requests share one SSO token request, which a sign-in timeout forgets so a retry asks Office again (13008 gets its own message); the sponsor picker offers Retry when the list fails to load.
- A timed-out gate post is checked against the run before anything is re-enabled ("may have been received" / "Not received — you can retry").
- Gate actions stay disabled after a post until a snapshot read after the post's own decision and idle (a click meanwhile is refused); Apply verdicts count only an idle after their own decision. A long job keeps the hold while the stream is connected ("Still working…" after 30 s of silence); the actions come back with "Status may be out of date — refresh." only when the stream is down or after 10 minutes.
- Onboard waits at most 20 s for Excel ("Excel is busy (finish editing the cell), then try again."); a late sheet removal is skipped. Apply's deferred re-render says "The change was sent; the Review sheet will refresh when Excel is free."
- Brief card redesigned automation-first: **Approve brief** is the primary action at the top, questions sit above the mapping under "Needs your input", the mapping reads as plain lines (confidence only when known, no "(n/a)"), and overrides are in a collapsed "Change mapping" disclosure with smaller secondary buttons. A column pick or **Use selected column** now only stages the change; it is posted by an explicit **Apply change** (one `set_column_binding`), and a new server binding discards the staged choice. While a change is staged, Approve is disabled, "Change mapping" opens, and the card shows "You have an unapplied mapping change. Apply it or discard it before approving." with a **Discard change** button that posts nothing. This way, a picked column is never silently lost on approval. Previously a single select change posted a gate. Activity lines are collapsed under "Activity". The existing Refresh button picks up the new secondary style.
- Contract test: freshness-gated waits, failure diagnostics, output kept in `.contract-last.log` (failing or interrupted runs also in `.contract-fail-*.log`).

## 0.1.0

First release of the Excel add-in.

- Task pane: sponsor picker, workbook upload with size, unsaved-file and integrity checks, live run progress over SSE with reconnect.
- Brief card, questions, column re-binding and highlight of the source sheet, header row, columns and finding rows.
- Findings list (acknowledge, exclude row with reason) and a protected Review sheet with ITEM_ID edit preview.
- Sign-off, artifact download (anchor and system browser routes).
- Auth: dev (`X-Actor`) and Entra SSO bearer; production builds refuse dev auth.
- Production hardening: manifest template and builder, CSP static web app config, bundle check (forbidden strings, source maps, size budget), accessibility and logging tests, placeholder icons.
